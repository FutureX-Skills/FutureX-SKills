# Skill: patent-analysis

## Purpose

用于分析专利文本、权利要求和专利组合，判断其保护范围、绕开难度、商业场景、潜在侵权或无效风险，为硬科技和深技术项目尽调提供输入。

## When to use

- 公司声称拥有专利壁垒或核心 IP 时。
- 硬科技、半导体、生物医药、机器人、新材料等项目尽调时。
- 需要判断专利是否覆盖关键产品能力或仅为防御性布局时。
- 需要为律师或专利专家访谈准备问题时。

## Inputs

- 专利号、专利全文、摘要、说明书、权利要求书、附图。
- 专利法律状态、申请人、发明人、申请日期、授权日期、地域。
- 公司产品说明、技术路线、竞品专利或公开论文。
- 专利专家、律师或技术团队的访谈纪要。

## Steps

1. 提取专利基础信息：标题、申请人、发明人、地域、时间、法律状态；无法确认则写「待验证」。
2. 拆解独立权利要求和从属权利要求，说明保护对象、关键限定条件和必要技术特征。
3. 将专利 Claim 与公司产品能力映射，判断是否覆盖核心商业场景。
4. 初步评估绕开难度：是否容易通过替代材料、流程、架构、参数或使用场景规避。
5. 检查专利壁垒来源：基础发明、工艺 know-how、组合专利、标准必要性、数据或制造经验。
6. 识别风险：法律状态不明、权利要求过窄、现有技术挑战、地域覆盖不足、所有权不清、侵权风险。
7. 区分投研判断和法律意见；需要专业判断处列入律师或专利代理人追问。
8. 输出对投资判断的影响和下一步核验材料。

## Quality checks

- 是否区分专利文本事实、公司自述和投研判断。
- 是否避免把「有专利」直接等同于「有壁垒」。
- 是否说明权利要求范围和商业产品之间的映射。
- 是否明确需要律师或专利专家确认的问题。
- 是否标记法律状态和所有权是否已验证。

## Restrictions

- 不得编造数据。
- 不得把公司自述当事实。
- 不得泄露敏感材料。
- 不得编造专利状态、授权范围、侵权结论、无效结论或法律意见。
- 不得泄露未公开专利、研发资料或公司技术细节。
- 不得把公司声称的专利壁垒当成已验证事实。
- 不得上传、外发或复制原始文件内容到外部服务。
- 必须遵守仓库根目录 `AGENTS.md`；如信息不足，必须明确标记「信息不足 / 待验证」并列出所需证据。
- 本 Skill 输出仅为投研分析，不替代律师或专利代理人意见。
