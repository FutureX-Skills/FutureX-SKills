# Skill: market-map

## Purpose

用于构建 FutureX 内部赛道图谱，梳理价值链、关键玩家、竞争分层、商业模式和投资切入点，为主题研究、项目定位和 sourcing 提供结构化地图。

## When to use

- 启动新赛道研究或投资主题时。
- 需要判断一个创业公司处于产业链哪个环节时。
- 需要比较竞品、替代方案和潜在收购方时。
- 需要为合伙人会议准备市场结构和机会窗口时。

## Inputs

- 赛道关键词、目标市场定义、地域范围和时间范围。
- 公司名单、竞品资料、客户访谈、行业报告、新闻、数据库摘录。
- 目标项目的 BP、官网、产品资料。
- 用户已知的投资假设或关注问题。

## Steps

1. 明确市场边界：服务对象、使用场景、地域、技术路径、商业模式和不纳入范围。
2. 梳理价值链：上游资源、中间基础设施、产品层、渠道、客户、付费方、监管方。
3. 将玩家分层：头部公司、成长公司、早期创业公司、开源项目、传统替代方案、潜在进入者。
4. 为每个玩家标记信息来源类型和证据状态；未知收入、客户、融资和估值统一写「待验证」。
5. 分析竞争维度：目标客户、产品形态、定价方式、部署方式、技术壁垒、渠道和生态位。
6. 识别市场驱动因素：技术变化、成本曲线、监管变化、客户预算、供应链变化、平台迁移。
7. 输出机会区和拥挤区：哪些环节存在需求缺口、利润池迁移或投资窗口；哪些环节可能过度竞争。
8. 给出 FutureX 可行动作：重点关注公司、需要补充访谈的问题、建议跟踪指标和下一步研究任务。

## Quality checks

- 市场边界是否清楚，避免把多个不同市场混在一起。
- 玩家分类是否基于客户、产品和商业模式，而不是只按融资阶段。
- 是否对市场规模、融资、收入、客户数量等数据标记证据状态。
- 是否给出 FutureX 可执行的 sourcing 或尽调动作。
- Mermaid 图是否能表达真实价值链关系，而不是装饰性图形。

## Restrictions

- 不得编造数据。
- 不得把公司自述当事实。
- 不得泄露敏感材料。
- 不得编造 TAM、CAGR、市场份额、竞品收入、客户数量、融资金额或估值。
- 不得把行业报告结论直接当作已验证事实；需标记为第三方报道并说明日期。
- 不得提交真实敏感材料或内部项目名单。
- 对缺少来源的玩家信息必须标记「待验证」。
- 不得上传、外发或复制原始文件内容到外部服务。
- 必须遵守仓库根目录 `AGENTS.md`；如信息不足，必须明确标记「信息不足 / 待验证」并列出所需证据。
