# Skill: memo-to-ic

## Purpose

用于将项目研究材料整理成 FutureX 投委会 memo，形成清晰的投资建议、证据基础、关键风险、估值与条款关注点以及 IC 需要决策的问题。

## When to use

- 项目准备进入 IC 讨论时。
- 已完成初筛、访谈、市场研究或尽调，需要统一成决策材料时。
- 合伙人需要看到投资假设、反证、风险和下一步条款建议时。
- 需要把零散材料转为标准化 memo 时。

## Inputs

- BP、One-Pager、市场图谱、Claim 核验表、风险 memo、访谈纪要。
- 财务、客户、技术、法律、竞品、融资和条款相关材料。
- 投资团队已有观点、争议点、待决策问题。
- 用户指定的 memo 篇幅和会议背景。

## Steps

1. 整理所有输入材料，建立证据索引，标记来源类型和日期。
2. 写出投资建议：投 / 不投 / 继续尽调 / 条件性推进，并说明决策所需证据。
3. 提炼投资假设：为什么现在、为什么这家公司、为什么 FutureX、可能的回报路径。
4. 用表格列出关键 Claim 和证据状态，确保公司自述不被写成事实。
5. 总结市场、产品、团队、商业化、财务、技术和竞争格局；缺证据处写「待验证」。
6. 写出反方观点和最大风险，说明什么证据会推翻投资假设。
7. 汇总估值和交易相关关注点；如缺少可靠融资或估值信息，写「待验证」。
8. 形成 IC 决策问题和会后行动清单。
9. 检查 memo 是否存在未标记来源的数据或敏感信息。

## Quality checks

- 是否把投资建议放在前面，并能被证据支持。
- 是否列出反方观点和反证信号。
- 是否所有关键数据都有来源和证据状态。
- 是否明确 IC 需要做什么决策。
- 是否删除或脱敏不应提交的真实敏感材料。

## Restrictions

- 不得编造数据。
- 不得把公司自述当事实。
- 不得泄露敏感材料。
- 不得编造融资金额、估值、收入、客户、市场规模、条款或退出假设。
- 不得把公司自述、媒体报道或团队判断写成已验证事实。
- 不得泄露真实交易条款、客户名单、财务底稿或内部投资意见到公开仓库。
- 不得上传、外发或复制原始文件内容到外部服务。
- 必须遵守仓库根目录 `AGENTS.md`；如信息不足，必须明确标记「信息不足 / 待验证」并列出所需证据。
- 估值、法律和税务内容只能作为投研输入，不能替代专业意见。
