# Skill: risk-memo

## Purpose

用于对单个投资项目进行反向风险分析，系统识别市场、产品、技术、团队、商业化、财务、法律、融资和退出风险，帮助 FutureX 决定是否推进、如何尽调和如何设计条款。

## When to use

- 项目进入复筛、尽调或 IC 前。
- 已有初筛材料，但投资亮点叙事过强，需要做反向审视。
- 合伙人要求明确「最大风险是什么」和「怎样验证」时。
- 投后或跟进项目出现重大变化时。

## Inputs

- BP、One-Pager、尽调材料、访谈纪要、产品资料。
- 财务数据、客户材料、合同样本、技术文档、竞品资料。
- 已形成的投资 memo 草稿或项目讨论纪要。
- 用户指定的重点风险领域。

## Steps

1. 建立项目事实底稿，区分已验证事实、公司自述、第三方报道、推测/判断和待验证。
2. 按风险类别逐项检查：市场、客户需求、竞争、产品、技术、团队、商业模式、财务、法律监管、融资、退出。
3. 对每个风险写清楚触发机制：什么条件下风险会发生，发生后会怎样影响增长、估值、融资或退出。
4. 评估风险等级：红色为可能阻断投资，黄色为需要核验或条款缓释，绿色为当前可接受。
5. 为每个红色和黄色风险列出证据状态、缺失材料和下一步验证方式。
6. 识别风险之间的传导关系，例如技术延迟导致销售周期拉长，进而影响下一轮融资。
7. 提出缓释动作：补充尽调、客户访谈、里程碑投资、保护性条款、保留观察、调整估值或拒绝。
8. 输出对投资建议的影响：继续推进、带条件推进、暂停、拒绝或等待新证据。

## Quality checks

- 是否覆盖主要 VC 风险类别，而不是只重复 BP 中的风险。
- 每个风险是否有触发机制、影响和核验动作。
- 是否明确哪些风险会阻断投资。
- 风险等级是否和证据一致。
- 是否避免把未经验证的公司解释当成风险已缓释。

## Restrictions

- 不得编造数据。
- 不得把公司自述当事实。
- 不得泄露敏感材料。
- 不得编造风险证据、财务数据、客户反馈、法律结论或监管状态。
- 不得泄露真实项目敏感材料。
- 不得把公司自述的缓释方案视为已完成验证。
- 不得上传、外发或复制原始文件内容到外部服务。
- 必须遵守仓库根目录 `AGENTS.md`；如信息不足，必须明确标记「信息不足 / 待验证」并列出所需证据。
- 法律、税务和监管内容只能作为投研风险提示，不能替代专业意见。
