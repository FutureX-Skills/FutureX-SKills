# FutureX 创意排版(电表设计系统)

把文章 markdown 转换为带设计系统的 .docx,用户在 Word 中全选复制、粘贴进微信公众号编辑器即可发布。色块与边线基于表格实现,粘贴后可保留。

## 工作流程

1. **确认配色**。用户未指定时,按题材推荐并请用户确认:

   | 配色 | 主色 × 强调色 | 气质 | 适用题材 |
   |---|---|---|---|
   | `amber` 琥珀 | 深空蓝 × 电表琥珀 | 工业冷静,硬派机构 | 数据分析、投资框架、口径拆解 |
   | `sage` 青金 | 深松绿 × 古金 | 学术古典,财经杂志 | 长文观察、政策解读、长期视角 |
   | `ember` 炭橙 | 石墨黑 × 火橙 | 杂志感,暖调叙事 | 案例研究、创业故事、portfolio 深访 |
   | `frost` 雾青 | 深钢青 × 湖蓝 | 冷调科技,克制 | 硬科技、芯片工艺、模型架构拆解 |

2. **把文章正文转写为标记方言**(见下),存为 `.md`。转写时的编辑判断见「标记决策」。

3. **构建**:
   ```bash
   node scripts/build_docx.js input.md <palette> output.docx
   ```

4. **必须做视觉校验**。渲染并逐页查看,确认无溢出、无错色、组件正常:
   ```bash
   python /mnt/skills/public/docx/scripts/office/soffice.py --headless --convert-to pdf output.docx
   pdftoppm -jpeg -r 90 output.pdf page && view page-*.jpg
   ```

5. 交付 .docx,并附一句使用说明(Word 打开 → 全选复制 → 粘贴进公众号编辑器)。

## 标记方言

```
# 标题第一行                                 ← 可连续多行 #,放最前
# 标题第二行

@series 天际的观察 | FUTUREX OBSERVATIONS   ← 眉头行,可选,紧跟标题下方,自动带强调色底线

正文段落直接写。[[关键数字或短语]] 会渲染为强调色加粗。

## 章节标题                                  ← 自动编号 01 02 03…

@readout 7 个季度 → 2 个季度 | 里程碑用时对比   ← 居中读数(16pt)+ 灰色小注
@readout! 27% | 2025 年 1 月 GRR 中位数        ← 特大读数(28pt),用于单个数字

> 金句放引块里。                              ← 暖底 + 强调色左边线

@cta                                        ← CTA 色块,首行为色块标题
天际资本 FutureX Capital
一家专注 AI 应用、AI 基础设施与集成电路的早期投资机构。
欢迎通过公众号后台与我们交流。
```

`---` 与空行被忽略(空行仅在 @cta 内表示色块结束)。

## 标记决策(转写时的编辑判断)

- **读数**:全文最多 2-3 处,只给最有冲击力的数字。对比型数字用 `@readout`(如「7 个季度 → 2 个季度」),单个震撼数字用 `@readout!`(如「27%」)。小注必须写清口径和来源。
- **金句引块**:每篇 2-4 处,选可独立成立的判断句,通常放章节末或全文末。不要把普通强调句都做成引块。
- **正文强调 `[[..]]`**:只用于关键数字和极少量短语,每节不超过 2 处,多则失效。
- **章节编号**:「写在最后」也会被编号,属于设计的一部分,无需处理。
- **CTA**:每篇需按文章主题定制收尾语,不要每次都照抄同一段"天际资本 FutureX Capital..."介绍语。内容以用户提供或文章自带的为准;拿不准合适的收尾内容时,和用户确认,不要自行发挥招揽话术。
- **眉头(@series)**:栏目名与英文译名需按文章主题拟定,不要每篇都固定写"天际的观察 | FUTUREX OBSERVATIONS"。若文章确实属于「天际的观察」等既有专栏可以沿用其名,否则根据这篇文章的主题另拟一个贴切的栏目名+对应英文译名,语域需与全文一致。

## 注意事项

- 脚本依赖预装的 `docx` npm 包,直接 require,勿先 npm install。
- 正文字号 11pt、行距 1.6,是为公众号移动端阅读校准的,不要改小。
- 特大读数(28pt)在移动端可能偏大,交付时提醒用户在公众号编辑器预览,过大可让 Claude 把 `@readout!` 降为 `@readout`。
- 如需新增配色,在 `scripts/build_docx.js` 的 `PALETTES` 中添加,需提供 6 个色值(ink/gray/primary/accent/accent2/quoteFill),深色主色 + 单一强调色是这套系统的设计约束,不要引入第三种彩色。
